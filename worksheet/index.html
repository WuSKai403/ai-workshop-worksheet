1我想做什麼

一句話就好：做給誰用？解決什麼問題？

範例　做一個網頁，讓教授和業界看到我的研究，並且能聯絡到我。

2別人打開後會看到什麼

照順序寫下來，從打開到離開。

範例　我的名字和照片 → 研究在做什麼 → 發表過的論文 → 怎麼聯絡我

3分成幾小步

每一步做完都要看得到東西。不知道怎麼分？直接問 AI：

問 AI 的話 我想做：（寫上「我想做什麼」那一句）。幫我拆成 3 到 4 個小步驟，每一步做完都要看得到畫面。先不要動手，列出來給我選。

動手前先猜要多久。AI 做出來很快，改到你要的樣子才花力氣——「做完應該長什麼樣子」寫得越清楚，改得越少。

4做完應該長什麼樣子

寫成一眼就能確認的樣子，做完一條一條對。AI 說「完成了」不算數。

範例　看得到我的名字和研究摘要　／　用手機看排版不會亂掉　／　沒有 AI 自己編的假內容

5我要跟 AI 說的話（進階）

把第一步寫成一段完整的話：要做什麼、內容從哪裡來、做到什麼程度。

範例　只用 HTML 和 CSS 做一個 index.html，不要裝任何套件。內容全部從 content.md 拿，不要自己編。動手前先告訴我你要建立哪些檔案。

6我的規則（寫進 AGENTS.md）

你糾正過 AI 的話，就寫一條下來，下次開新對話不用再講。

範例　改東西前先告訴我要改哪些檔案　／　不要裝任何套件　／　內容只從 content.md 拿

8我以為……結果……

今天最意外的一件事。例如：AI 一分鐘就生出網頁，但我花了十五分鐘才改到滿意。

改不動的時候，三條路

慢慢改　差一點點時最快。「標題太大，改成一半的大小」
打掉重做　改到第三次還不對就別再修。「這版不要了，重做一次，這次用單欄、左邊對齊」
要五個版本　自己也說不清楚要什麼時。「給我五個不同風格的版本，我看完再選」

名詞小抄

VS Code　寫程式用的編輯器，今天在這裡跟 AI 合作
AI agent　會自己讀檔、改檔、執行指令的 AI
AGENTS.md　寫給 AI 看的規則檔，它每次開工前會先讀
diff　AI 改了哪些地方，綠色是新增、紅色是刪除
Git　幫你記錄每一個版本的工具
GitHub　放程式碼的雲端空間
repo　GitHub 上的一個專案資料夾
commit　存一個版本，並寫一句改了什麼
push　把電腦上的版本傳上 GitHub
Cloudflare　把 GitHub 上的檔案變成網站的服務
部署　把做好的東西放上網路，讓別人看得到
自動部署（CD）　一 push，網站就自己更新

卡住時跟 AI 講清楚三件事：你看到什麼畫面、出現什麼錯誤訊息、剛剛做了什麼。只說「還是不行」，它只能再猜一次。
